Chief Stew

A macOS menu-bar app that shows, live, what the coding agents and builds in your git repos are doing, and what needs you: a Claude session asking a question or waiting for permission, a build waiting for your sign-off, finished work that isn't merged. Everything else stays quiet, so you can get on with other things while they run.

Any git repoWith no setup it shows each repo's agents. A repo that describes its workflow in .chiefstew.json also gets its builds, phases, gates, leftovers and roadmap.
The panel notifies, the window explainsThe panel shows what needs you, what's broken and what's moving. The window (⌘O) shows each repo's roadmap and the full detail of anything left behind.
It only displaysIt never runs builds or cleanup, and never changes a repo. Local only: no network listeners, no telemetry. Its one network access is checking its own repo for updates.

How it knows — status is the truth; events are hints

The repo's sweep · every 15 min
leaked databases, stray processes and routes
The roadmap file in git · when it changes

Adding a repo — the Add Repo wizard, about a minute
  1. Choose a repo, any git repo. Its agents show straight away.
  2. Install hooks: one click adds Claude Code hooks for every repo (backed up first; no repo changes).
  3. Build status (optional): Run setup prompt with your coding agent. It describes the repo's workflow in .chiefstew.json (data, not code) and checks it with chiefstew check; the wizard shows the result live. Or Start basic.
Rules it keeps
  • Facts, not guesses. A line is left out rather than inferred.
  • Needs you means yours. Teammates' work is listed, not chased.
  • Cleanup is copy-only. It shows the command; you run it.
  • A repo it can't read keeps its last good data, marked as such.
  • Updates are release tags, built and installed on your Mac.

Panel and window images are Chief Stew's own renders (the UI snapshot tests). All repos, builds and people are invented. Re-render: docs/mockup/render.sh.
